# Manuphet 使い方ガイド

## Manuphet とは

Manuphet（マニュフェット）は、**品目ごとの需要を AI で予測し、在庫がいつ足りなくなりそうかを教えてくれるツール**です。

- 過去の需要実績（出荷・販売・受注など）から、今後 1 か月・6 か月の需要を予測します
- 製品在庫と部品在庫が、予測どおりのペースで何日もつかを計算します
- 足りなくなりそうなときは、メールでお知らせします

## 開き方

ブラウザで次のアドレスを開きます（アドレスは管理者に確認してください）。

```
http://<サーバーのアドレス>:8000/
```

アドレスの末尾に `#data` や `#item=品目コード` を付けると、そのタブや品目を直接開けます。

---

## 画面の構成

| タブ | できること |
|------|-----------|
| **予測** | 品目を選んで、予測グラフと在庫の残日数を確認する |
| **データ入力** | 需要実績・在庫・部品構成を手入力する / CSV で取り込む |
| **MySQL連携** | 社内の MySQL データベースから必要なデータだけを取り込む |
| **学習管理** | AI に学習させる（1 品目ずつ / 全品目まとめて） |
| **品目設定** | 予測しない品目の除外、週次 / 月次の切り替え |
| **通知設定** | 在庫不足メールの送信先と送信元の設定 |

ヘッダー右側のボタン:

| ボタン | 説明 |
|--------|------|
| **再読込** | 登録データを読み込み直す |
| **通知チェック** | 在庫不足の見込みを今すぐ調べてメールを送る |
| **☽ / ☀** | ダークモードとライトモードを切り替える |

---

## はじめての流れ

1. 「データ入力」または「MySQL連携」で、**需要実績**を登録する（試すだけなら「サンプルデータを投入」）
2. 必要に応じて**在庫**と**部品構成**を登録する
3. 「予測」タブで品目を選び、「**学習**」を押す（数十秒〜数分）
4. グラフと「需要供給」パネルを確認する

---

## 1. 予測タブ

### グラフの見かた

| 線 | 意味 |
|----|------|
| **黄色の実線（ACTUAL）** | 実際の需要 |
| **水色の破線（BACKTEST）** | 直近の期間を「過去のデータだけで予測していたら」どうだったか |
| **桃色の点線（FORECAST）** | これからの予測（月次は 6 か月、週次は 12 週） |

黄色と水色が近いほど、予測が当たりやすい品目です。
グラフ上部の sMAPE は予測誤差の目安で、小さいほど精度が高いことを表します。

### 需要供給パネル

| 項目 | 意味 |
|------|------|
| **予測需要 1か月 / 6か月** | これからの需要の合計見込み |
| **製品在庫** | 登録されている製品の在庫数 |
| **在庫残日数** | 製品在庫が何日もつか（1 か月ペース / 半年ペースの 2 通り） |
| **部品在庫の表** | 部品ごとに、(製品在庫 + 部品在庫 ÷ 使用数) が何日もつか |

赤い「1か月以内」、橙の「半年以内」が付いた部品は、早めの手配を検討してください。
在庫が「未登録」のものは計算・通知の対象外です。

---

## 2. データ入力タブ

### 需要実績

予測のもとになるデータです。**日付・品目コード・数量**を入れて「追加」を押します（顧客は任意）。
同じ日に同じ品目が複数あっても、そのまま 1 行ずつ登録して構いません（予測時に月・週ごとに合計します）。

### 在庫

製品・部品の在庫数をコードごとに登録します。同じコードを登録すると上書きされます。
一覧の「編集」で入力欄に値を呼び出せます。

### 部品構成

「品目 1 台に、どの部品をいくつ使うか」を登録します。
部品の在庫数は「在庫」に部品コードで登録してください。

### CSV取込

1. 取込先（需要実績 / 在庫 / 部品構成）を選ぶ
2. CSV ファイルを選ぶ（先頭行のプレビューが表示されます）
3. 取込方法を選んで「取込」を押す

| 取込方法 | 動き |
|----------|------|
| 同じファイル名で取り込んだデータを置き換える | 毎月同じ名前のファイルを取り込み直す運用に便利 |
| 追加する | 既存のデータを残したまま追加 |
| 取込先のデータをすべて置き換える | 取込先のデータを全部消してから登録 |

CSV の例（1 行目は列名。日本語の列名でも可）:

```
record_date,item_code,quantity,customer
2025-01-15,ITEM-001,12,CUSTOMER-01
```

日付や数量が読み取れない行は取り込まれず、件数が表示されます。

## 3. MySQL連携タブ

社内の MySQL から、**必要な列と行だけ**を選んで取り込みます（MySQL のデータは変更しません）。

1. **接続設定**にホスト・データベース・ユーザー・パスワードを入れて「接続テスト」
2. **テーブルを選ぶ** — 中身の先頭 20 行が表示されます
3. **取込先と列の対応付け** — 「日付」「品目コード」「数量」などに、どの列を使うかを選ぶ（列名から自動で推測します）
4. **取り込む行を絞り込む**（任意） — 例: `status = shipped`、`order_date >= 2023-01-01`
5. 「**プレビュー**」で内容を確認し、「**取込**」を押す

「取込定義として保存する名前」を入れておくと、左側の一覧に保存され、
「実行」や「すべて同期」でいつでも最新のデータに取り込み直せます（月次自動再学習の前にも自動で同期されます）。

---

## 4. 学習管理タブ

- 左側の一覧で品目ごとに「学習」できます
- 「全品目を今すぐ学習」で、除外していない全品目をまとめて学習します（進み具合がバーで表示されます）
- 一度まとめて学習すると、以後 30 日ごとに自動で再学習します

データが少ない品目（月次 12 か月未満 / 週次 20 週未満）は、簡易なモデルで学習します。

---

## 5. 品目設定タブ

| 設定 | 使いどころ |
|------|-----------|
| **除外** | 取り扱いをやめた品目など、予測・学習・通知から外したいとき |
| **週次 / 月次** | 需要が多く週ごとの動きを見たい品目は週次。それ以外は月次 |

週次 / 月次を切り替えたら、その品目を学習し直してください。

---

## 6. 通知設定タブ

1. 「送信先」にメールアドレスを追加する
2. 「送信元メール（SMTP）」を設定して「保存」→「テスト送信」で確認する
3. 「自動通知を有効にする」にチェックを入れる

同じ品目・部品への通知は「初回 → 30 日後 → 180 日後」の最大 3 回です。在庫が増えるとリセットされます。

Gmail を使う場合はアプリパスワードが必要です（画面の「Gmail を使う場合」に手順があります）。

## よくある質問

**Q. グラフが表示されない**
A. まだ学習していない品目です。「学習」を押してください。バックテストには月次で 14 か月、週次で 18 週以上のデータが必要です。

**Q. 品目リストに何も出てこない**
A. 需要実績が登録されていません。「データ入力」または「MySQL連携」で登録してください。登録したのに出ない場合は「再読込」を押すか、「品目設定」で除外されていないか確認してください。

**Q. 通知メールが届かない**
A. 送信先の登録・SMTP 設定（テスト送信）・「自動通知を有効にする」を確認してください。在庫が未登録の品目・部品は通知されません。

**Q. 予測が合わない気がする**
A. データが増えるほど精度は上がります。最新のデータを登録してから学習し直してください。季節の動きが小さく週ごとの変動が大きい品目は、週次に切り替えると改善することがあります。
